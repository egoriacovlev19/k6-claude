# Стиль этого фреймворка

Пользователь хочет простой, быстро адаптируемый TypeScript.

Технический и бизнес-контекст проекта — в [CONTEXT.md](CONTEXT.md). Прочитайте его первым,
если видите этот репозиторий впервые.

- Пишите явные методы, понятные имена и короткие функции.
- Комментируйте назначение и неочевидное поведение на русском.
- Не добавляйте декораторы, глубокое наследование и универсальные фабрики без необходимости.
- Настройки UI-профилей и бюджеты сайта храните в projects/<project>/project.config.ts
  с пояснениями единиц. Настройки нагрузки (rps, VUs, пороги) — отдельно, в
  projects/<project>/load/scenario.js; core про них знать не должен (см. CONTEXT.md).
- Тест-данные (логины, пароли, всё, что перебирает data-driven тест) — в CSV
  projects/<project>/data/*.csv. Реальные файлы в .gitignore, в git — только *.csv.example.
- Настройки окружения и инфраструктуры (пути к бинарникам, порты, доступы) — в переменных
  K6_PERFORMANCE_*: системные или из .env.k6_performance (читает core/env.ts, системные в приоритете).
  Добавляйте переменную в .env.k6_performance.example только вместе с кодом, который её читает.
- Никаких паролей, токенов и ключей в закоммиченных файлах.
- Локаторы держите в Page Object, сценарий — в тесте, инфраструктуру — в core.
- Различайте время появления элемента и время последующей проверки его состояния.
- Не называйте ручную проверку через браузер успешным прогоном Playwright.
